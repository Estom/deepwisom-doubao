AtomStudio 大模型调用与多智能体编排架构
（基于源码绘制 · 示意）
一、调用分层：前端不接触模型，全部经平台插件
① 页面层 · WorkspacePage
消息流 / 输入框 / iframe 预览 · 触发 sendMessage
↓ 调用
② 编排层 · useWorkspace.runPipeline
硬编码 SOP，顺序触发各 Agent；构造每阶段输入、累积流式输出、落库版本
↓ capabilityClient.load(id).callStream('textGenerate', input)
③ 能力客户端 + 运行时插件
@official-plugins/ai-text-generate 1.0.21 · 平台负责鉴权 / 计费 / 流式传输
↓ 渲染 {{input.xxx}} 模板后请求
④ 大模型（modelID 2015）
temperature 0.5 · maxTokens 8192 · 流式返回 chunk.content
存储侧 · scopedStorage
类 localStorage 的键值库，键前缀 atomstudio_：
· users / session
· projects_{userId}
· messages_{projectId}
· tasks_{projectId}
· versions_{projectId}
↔ 编排层读写（非真实文件系统）

三、“读写文件”没有工具调用，由应用代码确定性模拟
“写文件” · Alex 输出后
流式文本累积
→ stripCodeBlocks 剥离 ```html
→ addVersion 存版本快照（scopedStorage）
→ currentCode 写入 iframe srcDoc
→ Blob 可下载 .html / 复制剪贴板
“读文件” · 迭代修改时
取最新版本 currentCode
→ 全文内联进 prompt：
“当前应用代码如下…请在此基础上修改”
→ 模型“看到”文件而非调用工具
“回滚” · 版本切换
rollbackToVersion
→ currentCode / currentVersion
指向旧快照
→ 预览即时还原
结论：LLM 仅承担“文本生成器”，提示词在 capability 模板中静态定义、运行时注入上下文；“文件读写”是模型之外的确定性代码（正则清洗 + KV 快照 + iframe 渲染 + Blob 导出），不存在 function-calling 工具循环。
